## 2. 범위

| | |
|---|---|
| **기간** | 2021 ~ 2026년, **6·7·8월만** (18개월) |
| **대상** | 미국 **국내선** 정기편 |
| **총 행 수** | **10,810,813편** |
| **모델 사용 행** | 9,102,252편 (train 5,408,935 / val 1,845,381 / test 1,847,936) |

**왜 여름만 쓰는가.** 분할을 연도로 하기 때문입니다. train/val/test의 계절 구성이 다르면
성능 차이가 "연도 차이"인지 "계절 차이"인지 구분할 수 없습니다. 여름 3개월로 고정하면
비교할 축이 연도 하나만 남습니다.

**왜 2021년이 포함되는가.** 학습에 쓰지 않습니다. 2022년 편에 붙일 "작년 성적표"의
재료로만 씁니다.

## 3. 분할

```
train   2022 · 2023 · 2024     성적표는 각각 2021 · 2022 · 2023 에서
val     2025                   성적표는 2024 에서
test    2026                   성적표는 2025 에서
```

무작위로 섞지 않습니다. 실제 사용 상황이 "과거로 배워 미래를 맞히는" 것이고,
무작위 분할은 같은 날 같은 공항의 다른 편을 학습과 평가에 동시에 넣어
그날의 날씨를 양쪽에 흘립니다.

연도 겹침이 0인 것은 `src/verify_leakage.py` 의 A그룹 점검이 확인합니다.

## 4. 변수 그룹 — 모델이 무엇을 볼 수 있는가

`src/config.py` 한 파일에 정의되어 있고, 감사 스크립트가 이 정의를 그대로 점검합니다.

| 그룹 | 개수 | 성격 | 모델 입력 |
|---|---:|---|:---:|
| 🟢 **A-1** | 9 | 예약 화면에서 손님이 보는 값 (월·요일·예정 시각·항공사·공항·거리·예정 소요시간) | ✅ 후보 |
| 🟢 **A-2** | 3 | 식별자 (`FlightDate`, `Flight_Number`, `Tail_Number`) | ❌ 조인·분할 전용 |
| 🔴 **B** | 5 | 결과 (`ArrDelay`, `Cancelled`, `Diverted`, `DivReachedDest`, `DivArrDelay`) | ❌ 정답 생성 전용 |
| 🟡 **C** | 13 | 사후 정보 (원인별 지연 분, 취소 사유, 실제 시각, 활주로 이동 시간 등) | ❌ "그날의 상태" 생성 전용 |

**`Tail_Number` 에 대하여.** 예약 시점에는 어느 기체가 투입될지 알 수 없습니다. 이 변수는
**과거 연도 데이터에서만**, 그것도 "그 기체의 그날 운항 사슬"을 복원하는 데만 씁니다.
복원한 결과를 편명·노선 키로 집계해 올해 편에 붙이므로, 올해 편에 대해 묻는 것은
"작년에 이 편명·이 노선이 어땠나"뿐입니다.

## 5. 파생 변수

| 묶음 | 개수 | 변수 |
|---|---:|---|
| 시각 변환 | 4 | `crs_dep_min` `crs_arr_min` `crs_dep_hour` `crs_arr_hour` |
| 이름표(키) | 3+1 | `flight_key` `route_key` `group_key` `substitute_level` |
| 연결편 | 5 | `day_seq` `is_first_flight` `turnaround_min` `prev_delayed` `absorbed` |
| 공항-날짜 | 4 | `n_flights` `mean_dep_delay` `fail_rate` `bad_day` |
| 과거 이력(성적표) | 5 | `A_absorb_rate` `B1_turnaround_mean` `B2_day_seq_mean` `B3_first_flight_rate` `C_bad_day_rel_fail` |
| ↑ 위 세 줄 | — | 기각됨. `src/archive/` 참조 |
| **시간표 파생** | **3** | **`sched_pad` `dest_arr_load` `days_to_nearest_holiday`** ← 모델 입력 |
| 그날의 유형 | 2 | `scen_origin` `scen_dest` (5유형, 14단계 모델 B 전용) |
| 정답 | 1 | `y_class` (10구간) |

**모델 입력은 12개**입니다 — A-1 에서 바로 오는 9개와, 공개 시간표·작년 공개 기록에서
만든 3개(`sched_pad` · `dest_arr_load` · `days_to_nearest_holiday`)입니다.
셋 모두 앞의 9개로는 재구성되지 않는다는 것이 선정 기준이었습니다.
전처리 후 선형 설계행렬은 **355열**이 됩니다.

## 6. 정답 — 10구간

| 번호 | 구간 | train 비중 |
|---:|---|---:|
| 0 | ≤ 0분 (조기·정시) | 57.30% |
| 1 | 0–15분 | 16.46% |
| 2 | 15–30분 | 7.59% |
| 3 | 30–60분 | 7.16% |
| 4 | 60–90분 | 3.43% |
| 5 | 90–120분 | 1.95% |
| 6 | 120–180분 | 2.00% |
| 7 | 180–300분 | 1.28% |
| 8 | 300분 초과 | 0.65% |
| 9 | 미도착 (결항·회항 실패) | 2.20% |

- 회항했지만 목적지에 **도착한** 편은 별도 사건이 아니라 **아주 늦은 도착**이므로
  `DivArrDelay` 로 지연 구간에 넣습니다. 미도착은 결항과 "회항 후 목적지 미도달"뿐입니다.
- **이상치를 제거하지 않습니다.** 꼬리(300분 초과·미도착)가 곧 상품입니다 —
  "90% 보장 시각"은 분포의 꼬리에서 읽히므로, 꼬리를 자르면 보장이 낙관적으로 틀어집니다.
