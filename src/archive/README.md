# archive — 시도했고 기각한 변수군

여기 있는 네 스크립트는 **과거 운항 이력 변수 5종**을 만들고 검정한 코드입니다.
**최종 모델은 이 변수들을 쓰지 않고**, 보고서도 다루지 않습니다.
기록으로 남겨 둡니다.

| 파일 | 하는 일 |
|---|---|
| `step03_legs.py` | 같은 기체의 직전 비행 연결 (`day_seq`·`turnaround_min`·`absorbed` 등) |
| `step04_airport_day.py` | (출발공항, 날짜)별 상태와 "나쁜 날" 판정 |
| `step05_history.py` | 키별 작년 성적표 5종 생성, 평활 강도 k 를 경험적 베이즈로 추정 |
| `step10_feature_selection.py` | 변수 블록 게이트 — 넣어서 좋아지는지 판정 |

## 왜 기각했는가

판정 기준을 **숫자를 보기 전에** 고정했습니다. 같은 설정을 시드만 바꿔 세 번
돌려 실행 간 잡음을 재고(sd 0.000133), 그 2배인 **0.000265** 를 임계값으로 삼았습니다.

| 블록 | val log loss 개선폭 | 판정 |
|---|---:|---|
| + A 흡수율 | −0.000043 | 미달 |
| + B 연결편 3종 | −0.000052 | 미달 |
| + C 나쁜 날 상대실패 | +0.000098 | 미달 |
| + A·B·C 전부 | +0.000222 | 미달 (임계값 바로 아래) |
| + 그날의 유형 | +0.048182 | 통과 — 단 예약 시점에 알 수 없어 배포 불가 |

단독으로는 정시 비율을 12~15%p 갈랐던 변수들입니다(`results/step08_feature_spread.csv`
가 그 수치를 남기고 있습니다). 그런데 넣어도 움직이지 않았습니다.

이유는 구체적입니다 — 작년 기록을 찾을 때 계층 축소를 쓰는데, train 행의 **69.1%**
가 `route_key`(= 항공사 + 출발공항 + 도착공항)에서 값을 받습니다. 그 세 변수는 이미
모델 입력이므로, 대부분의 행에서 이 변수들은 **모델이 이미 가진 열로 계산되는 값**
이었습니다.

측정 결과는 `results/step10_gate.csv` 와 `results/step10_noise.csv` 에 있습니다.

## 주의 — 아직 실행은 됩니다

`src/step07_dataset.py` 가 이 변수들을 데이터셋에 조인하고(모델 단계에서 다시
떨굽니다), 그래서 `run_all.py` 는 여전히 이 네 단계를 실행합니다.
`archive` 는 **"보고서에서 다루지 않는다"** 는 뜻이지 "실행되지 않는다"는 뜻이
아닙니다. 파이프라인에서 완전히 떼어내려면 `step07`·`step08`·`step09`·`step11`·
`verify_leakage` 를 함께 고치고 7~9단계를 다시 돌려야 합니다.
