## 1. Introduction

### 1.1. 연구 배경 및 문제 정의

- 항공권의 "19:00 도착"은 약속이 아니라 **계획**이다. 손님은 그걸 약속으로 믿고
  일정을 짠다.
- **근거 숫자**: 예정 시각 이내 도착 **57.3%** / 90%가 지켜지는 지점 **+73분** /
  95% **+154분** → `step08_class_distribution.csv`, 그림 `step08_class_distribution.png`
- **"늦었다"의 기준이 사람마다 다르다** → 고정 임계값 이진 분류로는 답할 수 없다.
  (18:00 마감인 사람과 21:00 마감인 사람에게 같은 답밖에 못 줌)

### 1.2. 연구 목적 및 주요 기여

- **목적**: 하나의 시각 대신 **10구간 확률 분포**를 예측하고, 마감 시각과 요구 확률을
  사용자에게 넘겨 **"그 마감을 지키는 가장 늦은 편"** 을 계산한다.
- **포기한 것과 남긴 것** — 이 구분이 보고서 전체의 축:
  - 포기: "어느 편이 더 안전한가" **순위 매기기** → 상식("첫 편을 타라")이 이미 이긴다
  - 남김: **경계 계산** → 사람이 머리로 못 하는 건 이것뿐
- **기여 4가지**
  1. 예약 시점 정보만으로 10구간 분포를 예측하고 **보정**해, test 2026에서
     90% 약속의 실제 이행률 **91.3%** 달성
  2. 예약 시점 정보의 **천장을 측정** (AUC 0.696, 그날을 알면 0.751)
  3. **분해는 정보를 만들지 않는다**를 실증 (합성 vs 무조건 차이 −0.00368)
  4. 확률을 **언제 측정한 자료로 보정해야 하는가**를 실험으로 답함 —
     "가장 최신"이 아니라 **계절 구성이 같은 작년**이다

## 3. Approach (Method)

### 3.1. 전체 연구 프레임워크

한 단계 = 한 파일(`src/stepNN_*.py`), `python run_all.py` 로 재현.
모델 입력은 **예약 시점 시간표 12변수**다.

```
[재료]    1 수집 → 2 정제·키·10구간 라벨 → 3 시간표 파생 3변수 → 6 그날의 유형
[데이터셋] 7 결합·연도 분할 → 8 EDA(설정값 확정) → 9 전처리 두 벌
[모델링]   11 모델 3종 → 12 보정 → 13 해석 → 14 시나리오
[서비스]   15 서비스 평가(test 2026) → 16 데모 데이터
```

### 3.2. 도착 지연 구간 및 확률 분포 정의

- 10구간 (≤0 / 0–15 / 15–30 / 30–60 / 60–90 / 90–120 / 120–180 / 180–300 / 300분+ / 미도착)
- **출력 하나에서 화면 전부가 나온다**:
  ```
  누적합 → "몇 분 안에 도착할 확률"
  역으로 → "90% 보장 시각"
  10번째 칸 → 결항·회항실패 위험
  ```
- **설계 근거**: 회항 후 목적지에 **도착한** 편은 별도 사건이 아니라
  *아주 늦은 도착*이므로 `DivArrDelay` 로 지연 구간에 넣는다. 미도착은 결항과
  회항 실패뿐.
- **이상치를 제거하지 않는 이유**: 꼬리가 곧 상품. 90% 보장 시각이 꼬리에서 읽힌다.

### 3.3. 데이터 전처리

- **변수 4그룹** (`src/config.py` 한 파일에 정의 → 감사 스크립트가 그대로 점검)

  | 그룹 | 개수 | 모델 입력 | 쓰임 |
  |---|---:|:---:|---|
  | 🟢 A-1 | 9 | ✅ 후보 | 예약 화면에서 보이는 값 |
  | 🟢 A-2 | 3 | ❌ | 식별자 — 조인·분할 전용 |
  | 🔴 B | 5 | ❌ | 정답 생성 |
  | 🟡 C | 13 | ❌ | "그날의 상태" 생성 |

- **`Tail_Number` 를 쓰면서도 누출이 아닌 이유** (한 문단 필요):
  예약 시점엔 어느 기체가 올지 모른다 → **작년 데이터에서만** 운항 사슬 복원에 쓰고,
  결과를 편명·노선 키로 집계해 붙인다. 올해 편에 묻는 건 "작년에 이 편명·이 노선이
  어땠나"뿐.
- **모델 입력 12개.** 예약 화면에서 그대로 읽히는 9개와, 공개 시간표·작년 공개
  기록에서 계산되는 3개다.

  | | 변수 | 비고 |
  |---|---|---|
  | 시간표 9 | 항공사 · 출발공항 · 도착공항 · 요일 · 월 · 예정 출발시 · 예정 도착시 · 거리 · 예정 소요시간 | 표에 적혀 있는 값 |
  | 파생 3 | `sched_pad` | 예정 소요시간 − 작년 같은 노선 실제 소요시간 중앙값 |
  | | `dest_arr_load` | 그 날짜·그 시각에 도착지로 들어오는 편 수 |
  | | `days_to_nearest_holiday` | 가장 가까운 연방 공휴일까지의 부호 있는 일수 |

  시각은 `1435` 같은 표기를 **자정부터의 분**으로 바꿔 쓴다
  (`1359` 와 `1400` 은 1분 차이인데 정수로는 41 차이).

- **전처리 후 차원 — 원변수 12개가 설계행렬 355열이 된다** (요구사항 대응)

  선형 모델은 "ATL" 을 읽지 못한다. 공항에 1·2·3 번호를 매기면
  *"ATL 과 DEN 사이에 DFW 가 있다"* 는 **거짓 순서**가 생기므로, 범주 하나하나를
  0/1 열로 펼친다(원-핫).

  | 변수 | 열 수 | 내역 |
  |---|---:|---|
  | 항공사 | 18 | 17개 + 기타 |
  | 출발 공항 | 137 | 상위 136개 + 기타 |
  | 도착 공항 | 137 | 상위 136개 + 기타 |
  | 예정 출발시 | 24 | 0~23시 |
  | 예정 도착시 | 24 | 0~23시 |
  | 요일 | 7 | |
  | 월 | 3 | 6·7·8월 |
  | 거리 · 예정 소요시간 | 2 | 수치형 그대로(결측 대치 후 표준화) |
  | 파생 3종 | 3 | `sched_pad` · `dest_arr_load` · `days_to_nearest_holiday` |
  | **합계** | **355** | |

  트리 모델(XGBoost)은 범주를 그대로 쓸 수 있어 **12열**을 받는다.
  같은 변수에서 **두 벌**을 만드는 이유는 §3.6.1 참조. 그 선택이 주장이 아니라
  측정이라는 근거는 §5.1.4 — 같은 다항 확장을 두 모델에 똑같이 줘 봤다.

### 3.4. 시나리오 유형 정의 및 분류 방법

- 5유형 × (공항, 날짜) 단위
- **설계 원칙 2가지**:
  1. **편이 아니라 공항-날짜에 붙인다.** 편에 붙이면 *결과로 결과를 설명*하는 꼴 —
     BTS는 **늦은 편에만** 원인을 기록하므로 정시 편과 비교할 기준이 없다.
  2. **leave-one-out.** 하루 20편짜리 공항에서는 그 편이 자기 답을 읽게 되므로,
     모든 집계에서 해당 편을 뺀다. 하루 20편 미만은 아예 라벨하지 않음.
- **원인 구성비는 공항 안에서 표준화한 뒤 argmax** — 로키산맥 옆 공항은 늘 날씨 분이
  있으므로 "그 공항 기준으로 이상한 구성"이어야 그날의 특징.
- **유형 이름과 개수는 우리가 발명한 것이 아니다** — BTS가 기록하는 5개 지연 사유
  컬럼에서 왔다. 보안(전체 분의 **0.18%**)을 빼고 4개 + 정상일 = 5유형.
  우리가 정한 것은 **분류 절차**이지 범주가 아니다.

### 3.5. 탐색적 데이터 분석(EDA) 방법

**보는 범위를 둘로 나눴다.**
- **설정값 결정** → **학습 연도만** (2022–24). val·test는 열지 않음.
  평가 연도의 분포를 눈으로 본 것만으로도 선택에 영향을 준다.
- **구조 기술** → 전 기간. 사후 정보의 기술통계일 뿐이므로 **설계 근거로 쓰지 않음**.

**EDA가 정한 설정값 (데이터 기반, 임의 숫자 없음)**

| 설정값 | 정한 값 | 근거 |
|---|---|---|
| 원-핫 공항 수 | 367개 중 **136개** | 학습 연도 누적 운항 95% 지점 |
| 나쁜 날 기준 | 공항·연도 상위 10% | p90 임계값이 **−8.5~199.0분**으로 흩어짐 |

### 3.6. 예측 모델 및 확률 보정 방법

**3.6.1 알고리즘 3종**
다항 로지스틱 회귀 / XGBoost / MLP — **셋 다 10구간 확률을 출력**하게 맞춰야
비교가 성립. 선형용 원-핫 **355열** / 트리용 범주 유지 **두 벌 전처리**
(각 모델에 불리한 형태를 주면 "모델 비교"가 아니라 "형태 비교"가 됨).
**이 주장은 §5.1.4에서 측정으로 확인한다** — 선형 모델에 곡선을 그릴 수 있게 해 주면
실제로 달라지는지, 같은 것을 트리에 줘도 달라지는지.

**3.6.2 모델 A · B · C**

| | 정의 | 역할 |
|---|---|---|
| **A** | `P(y\|x)` 무조건 | ✅ **실제 배포 모델** |
| **B** | `P(y\|x, s)` 참 유형 주입 | ❌ 배포 불가. **① 천장 측정 ② C의 부품 ③ what-if 패널** |
| **C** | `Σ_s C(s\|x)·B(y\|x,s)` | ✅ 배포 가능. "분해가 정보를 만드는가" 검정용 |

- **모델은 5개가 아니라 1개**: 유형은 **입력 칸**이지 모델을 나누는 기준이 아니다.
  (5개로 나누면 ① 희귀 유형은 배울 데이터가 없고 ② 공통 규칙을 5번 다시 배우고
  ③ 유형별 차이인지 모델이 달라서인지 구분 불가)
- **합성의 구현**: 출발지·도착지 유형을 독립으로 예측해 **25개 조합**을 가중 평균.
  (독립 가정은 한계로 명시)

**3.6.3 확률 보정**
- **왜**: 파는 게 확률 그 자체. 90%라 말하고 85%면 **상품이 거짓말**.
  모델은 "분포 전체가 맞게" 학습되지 "90%라 한 게 정확히 90%"를 보장하지 않는다.
- **어떻게 재는가**: 개별 편은 검증 불가(도착/미도착 둘 중 하나).
  **같은 확률을 받은 편들을 모아서 센다** — 일기예보 검증과 동일. 8개 경계 전부에서.
- **어느 구간으로 만드는가도 실험으로 결정** (보정 없음 / 작년 같은 세 달 /
  직전 달 / 롤링 14일) ← 이게 §5.2.1의 반직관적 결과
- **방식 4종**: isotonic / temperature / prior 보정 / prior+isotonic

### 3.7. 목표 시각 도착 확률 기반 항공편 추천 알고리즘

```
여유        = 마감 − 예정 도착            (음수면 탈락)
마감 준수 확률 = 분포에서 여유 안에 도착할 확률
보장 도착 시각 = 분포에서 요구 확률이 되는 지점
답          = 준수 확률 ≥ 요구 확률인 편 중 출발이 가장 늦은 편
```

**꼭 적을 것 — 하지 않는 두 가지**
1. **결항 확률을 다시 곱하지 않는다.** 분포는 이미 "도착할 확률"이고 미도착은 빠져
   있다. 또 곱하면 **두 번 깎는** 셈. 결항 위험은 화면에 **따로** 표시.
2. **보장 시각을 억지로 만들지 않는다.** 요구 확률에 도달 못 하는 편은
   **"보장 불가"** 로 표시.

## 4. Experiment

### 4.1. 데이터셋 구성 및 탐색적 데이터 분석

- BTS 2021–2026년 6–8월, **10,810,813편**. 퍼블릭 도메인, 개인정보 없음.
- **왜 여름만**: 분할을 연도로 하므로 계절 구성이 같아야 한다. 아니면 성능 차이가
  "연도 차이"인지 "계절 차이"인지 구분 불가 → **비교할 축을 하나만 남긴다.**
- **분석 범위는 2022–2026년**. 2021년은 2022년 편의 `sched_pad` 를 계산하기 위한
  직전 해 자료로만 쓰인다(§3.3).
- **품질 점검**: 설명 안 되는 결측 **1행 / 1,081만** (숨기지 않고 셈)
- EDA 관측 → 설계 대응표 (아래가 §5·§6에서 반복 인용됨)

  | 관측 | 숫자 | 설계로 이어진 결과 |
  |---|---|---|
  | 출발 시각별 | 05시 정시 **77.7%** → 20시 **43.5%** → 23시 반등 | **직선 아님** → 선형 모델엔 시각 원-핫 |
  | 지연 원인 구성 | **연결편 40.7%** · 항공사 34.5% · NAS 18.4% · 날씨 6.2% | 연결편 변수를 만든 근거 |
  | 시각별 원인 구성 | 05시엔 연결편 지연 거의 없음 → 시간 갈수록 증가 | 시각·순번의 **중복 계상** 경고 |
  | 하루 후보 편수 | 중앙값 3편, **단일 편 30.8%** (test 2026, 147,727/479,271) | 서비스 한계 |

### 4.2. 학습·검증·보정·평가 데이터 분할

```
train  2022·2023·2024  (5,408,935)
val    2025            (1,845,381)   ← 보정 구간도 겸함
```

  **그날의 날씨가 샌다.**
- **보정 구간 실험 설계**: 모델을 2022–23으로 재학습해 2024와 2025를 모두 미지로

- 알고리즘 3종 비교 — 동일 분할·동일 지표

- **특성공학·규제 실험** (5주차 주제) — `src/step11c_polynomial.py`
  - 수치형 **5변수만** 차수 1·2·3으로 확장. 원-핫 350열은 펼치지 않는다
    (2차로 가면 약 61,000열이 되는데 그건 모델링이 아니라 메모리 문제이고,
    지시변수 두 개의 곱은 트리가 두 번 갈라 이미 만든다)

### 5.1. 모델별 예측 성능 비교

**5.1.1 알고리즘 3종** (val 2025)

| 모델 | log loss | CDF 오차 | AUC | 학습 |
|---|---:|---:|---:|---:|
| M1 다항 로지스틱 | 1.40590 | 0.00751 | 0.69427 | 141초 (미수렴, 그대로 보고) |

**세 모델의 폭 0.00556** → 천장은 모델이 아니라 변수.
**정직하게 쓸 것**: MLP가 log loss에서 **0.00439** 앞선다(시드 잡음의 33배, 실재하는
차이). 그럼에도 XGBoost를 배포했다. 이유는 **우리가 처음에 선언한 최종 지표**다 —
확률의 정직함(CDF 보정오차)에서 XGBoost가 0.00654로 가장 좋고 MLP는 0.00789다.
log loss는 분포 전체의 평균 점수이고, 우리가 파는 것은 "90%"라는 **약속 한 줄**이다.
덧붙여 XGBoost는 355열 설계행렬 없이 12열을 그대로 먹고, **정확한 TreeSHAP**을 준다.
→ *"약속의 정직함을 위해 log loss 0.0044를 지불했다."* 오라클 격차(0.055)의 1/13.

임계값을 넘는다. 단일 시드의 −0.00046이 시드 평균에서 −0.00029로 줄었으므로 절반

선언한 지표 우선순위를 그대로 따른다.

**덤으로 얻은 것**: 10단계가 1/3 표본에서 잰 시드 잡음 sd 0.000133과, 전체 학습셋에서
다시 잰 0.000125가 거의 같다 — **숫자를 보기 전에 고정한 임계값이 과하지도 느슨하지도
않았다**는 사후 증거다.

**6.1.4 가정이 바뀌면 답이 바뀐다 — what-if 패널**

| 날씨일 | 42.8% | 5.9% | **+113분** | **20.1%** |

정상일 +33분 vs 날씨일 +113분 — **같은 편인데 가정만 바꿔도 80분 이동.**
이것이 시나리오 유형을 만든 **유일한 산출물**이다(성능이 아니라 화면).

**6.1.5 보정 효과** — §5.2.2를 해석. log loss가 나빠지면서 ECE가 좋아지는 것은
**두 목표가 다르다**는 증거.

### 6.2. 추천 실패 사례 및 예측의 한계

| 한계 | 숫자 | 영향 |
|---|---|---|
| **특정 항공사에서 약속이 깨짐** | **OH 84.6%** (−5.36%p, n=63.5k), YX 88.1%, OO 89.3% | 90% 약속이 그 손님에겐 85%. **서비스 경고 필요** |
| 80% 약속 과보수 | +3.55%p | 필요 이상으로 일찍 떠나게 만듦 |
| 선택지 없는 노선 | 단일 편 노선-날짜 **30.8%** (147,727 / 479,271) | "가장 늦은 편 고르기"가 성립 안 함 |
| 시뮬레이션 마감 정의 느슨 | 마지막 도착 +60분 | 답이 대체로 "마지막 편". 마감 폭 스윕은 향후 과제 |
| 합성은 1/4 부분집합 | 461,346행 | 25개 조합 × 전체는 비용 과다 |
| 유형 독립 가정 | — | 출발지·도착지 유형을 독립으로 예측해 합성 |
| 로지스틱 미수렴 | max_iter=120 (120회에서 중단) | 더 돌리면 약간 개선 가능. 그대로 보고 |
| 범위 | 미국 국내선 **여름만** | 겨울·국제선 일반화 불가. 가격·실시간 없음 |

**윤리** — 이 자리에 반 쪽
1. **약점 공개의 양면성**: OH의 84.6%를 적는 건 특정 회사에 불리하다. 그러나 적지
   않으면 **그 손님에게는 약속이 조용히 깨진다.** 표본 수와 함께 공개하는 쪽을 택함.
2. **잘못된 자신감의 위험**: 이 서비스는 사람을 **더 늦은 편에 태운다.** 틀리면 손해가
   실재한다. 그래서 (a) 보정 필수 (b) "보장 불가" 숨기지 않음 (c) 최종 지표를 점수가
   아니라 **약속 이행률**로 삼음.
3. 개인정보 없음 · 퍼블릭 도메인 데이터.

## 7. Conclusion

**세 문장으로**
1. 표에 적힌 도착 시각은 57%짜리 약속이고, 우리는 **90%짜리 약속**을 만들었다
   (test 2026 실제 이행 **91.3%**).
2. 변수를 더 넣어도, 모델을 바꿔도, 하이퍼파라미터를 돌려도 움직이지 않았다 —
   **예약 시점 정보의 천장은 AUC 0.696**, 그날을 알면 0.751. 그 격차가
   이 문제에서 **실시간 정보의 값**이다.
3. 이 프로젝트가 남기는 것은 성능 숫자가 아니라 **판정의 기준**이다 — 모든 선택을
   숫자를 보기 전에 고정한 임계값으로 판정했다.

**향후 확장**: 겨울·국제선 · 마감 폭 스윕 · 항공사별 경고 · 실시간 정보 결합 시 기대 이득(+0.055 상한)
