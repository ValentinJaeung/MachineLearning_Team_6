# 26-2-Team-6 — 비행기 도착 시각 예측

> 아주대학교 인공지능융합학과 · **기계학습기초(AAI332)** 2026-2학기 팀프로젝트 6조

**항공사가 알려주는 도착 시각은 약속이 아니라 계획입니다.**
학습 데이터에서 예정 시각 이내 도착은 **57.3%** 뿐이고, 90%가 지켜지는 지점은
예정 도착 **+73분**입니다. 이 프로젝트는 "내가 원하는 확률로 지켜지는 도착 시각"과,
그 위에서 **마감을 지키는 가장 늦은 편**을 찾아 주는 서비스를 만듭니다.

```
손님이 입력:  노선 · 날짜 · 몇 시까지 도착해야 하는지 · 몇 %로 확실해야 하는지
서비스가 답:  그 마감을 지키는 가장 늦은 편 + 보장 도착 시각 + 결항 위험
```

"안전하려면 첫 비행기를 타라"는 상식이 이미 답을 줍니다. 상식이 계산하지 못하는 것은
**경계** — 약속을 지키면서 가장 늦게 떠날 수 있는 편 — 뿐이고, 그것만 남겼습니다.

```powershell
pip install -r requirements.txt
```

```powershell

```

양쪽으로 새기 때문입니다.

## 설계 원칙

**1. 임의로 고른 숫자를 두지 않는다.**
평활 강도는 경험적 베이즈로 추정하고(k_A 3.99 · k_C 4.04), 원-핫할 공항 수는 학습
연도 누적 운항 95% 지점(136개)에서 끊고, "나쁜 날"은 절대 분(分)이 아니라 공항·연도
상대 분위로 자릅니다. 절대 기준이 안 되는 이유도 측정해 두었습니다 — p90 임계값이
공항·연도별로 **−8.5분에서 199.0분**까지 흩어집니다.

**2. 변수는 상관이 아니라 기여로 판정한다.**
단독으로 정답을 잘 가르는 변수여도, 이미 있는 변수가 같은 정보를 담고 있으면 넣어도
아무것도 바뀌지 않습니다. 그 "바뀌었다"의 기준을 사후에 정하면 아무 숫자나 근거가
되므로, 같은 설정을 시드만 바꿔 세 번 돌려 잡음을 먼저 재고(sd 0.000133) 그 2배를
**숫자를 보기 전에** 임계값으로 고정했습니다.

**3. 약속한 확률이 실제로 지켜지는지를 최종 지표로 삼는다.**
우리가 파는 것은 확률 그 자체입니다. 다른 점수가 아무리 좋아도 "90%"라고 말한 것이
실제로 85%라면 상품이 거짓말입니다.

**4. 버릴 때마다 왜 버리는지 측정하거나 논증한다.**
기각한 가설과 그 근거가 `results/` 에 전부 남아 있습니다.
