# 1. Introduction

### 1.1 연구 배경 및 문제 정의

**할 말** — 항공권의 "19:00 도착"은 약속이 아니라 계획이다. 그리고 "늦었다"의 기준이

| 95%가 지켜지는 지점 | **+154분** |
| 미도착(결항·회항실패) | **2.20%** |

### 1.2 연구 목적 및 주요 기여

**할 말** — 분포를 예측하고, 마감과 요구 확률을 손님에게서 받아 경계를 계산한다.
**포기한 것과 남긴 것**을 먼저 가른다. 이 구분이 보고서 전체의 축이다.

- 포기: "어느 편이 더 안전한가" **순위 매기기** → 첫 편을 타라는 상식이 이미 이긴다
- 남김: **경계 계산** → 사람이 머리로 못 하는 것은 이것뿐

**기여 4가지** (이 순서로)
1. 예약 시점 정보만으로 분포를 예측·보정해 **test 2026에서 90% 약속의 실제 이행률 91.3%**
2. 예약 시점 정보의 **천장을 측정** — AUC 0.696, 그날을 알면 0.751
3. **분해는 정보를 만들지 않는다**를 실증 — 합성 1.40060 vs 무조건 1.40428
4. 확률을 **언제 측정한 자료로 보정해야 하는가**를 실험으로 답함 — "가장 최신"이 아니라
   **계절 구성이 같은 작년**

### 3.2 도착 지연 구간 및 확률 분포 정의

**할 말** — **출력 하나에서 서비스 화면 전부가 나온다.** 10구간을 누적하면 "몇 분 안에
도착할 확률", 거꾸로 읽으면 "90% 보장 시각", 10번째 칸이 결항 위험이다.

구간: `≤0 / 0–15 / 15–30 / 30–60 / 60–90 / 90–120 / 120–180 / 180–300 / 300분+ / 미도착`

**설계 근거 두 개** (각 한 문장)
- 회항 후 목적지에 **도착한** 편은 별도 사건이 아니라 *아주 늦은 도착*이므로
  `DivArrDelay` 로 지연 구간에 넣는다. 미도착은 결항과 회항 실패뿐이다.
- **이상치를 제거하지 않는다.** 꼬리가 곧 상품이다 — 90% 보장 시각이 꼬리에서 읽힌다.

**할 말** — 모델 입력은 **12개**, 전처리 후 선형 설계행렬은 **355열**이다. 변수 4그룹을

| | 변수 | 비고 |
|---|---|---|
| 시간표 9 | 항공사 · 출발공항 · 도착공항 · 요일 · 월 · 예정 출발시 · 예정 도착시 · 거리 · 예정 소요시간 | 표에 적혀 있는 값 |

**355열 내역** — 항공사 18 + 출발공항 137 + 도착공항 137 + 출발시 24 + 도착시 24 +
요일 7 + 월 3 + 수치형 5 = **355**. 트리 모델은 범주를 그대로 먹으므로 **12열**이다.

**꼭 적을 두 문단**
- **왜 원-핫인가**: 선형 모델에 공항 번호를 매기면 *"ATL과 DEN 사이에 DFW가 있다"* 는
  거짓 순서가 생긴다. 시각도 `1435` 를 자정부터의 분으로 바꿔 쓴다 — `1359` 와 `1400`

- **`sched_pad` 가 누출이 아닌 이유**: 실제 소요시간은 사후 정보지만, 읽는 것은
  **작년 그 노선의 중앙값**뿐이다. 그 편 자신의 실제 소요시간은 들어가지 않는다.
  이것은 주장이 아니라 점검 항목이다 — 노선·연도·예정시간이 같은 두 편은 `sched_pad`
  가 같아야 하고, 누출 감사가 전 분할에서 확인한다(E그룹).

### 3.4 시나리오 유형 정의 및 분류 방법

**할 말** — **유형 이름과 개수는 우리가 발명한 것이 아니다.** BTS가 기록하는 5개 지연
사유 컬럼에서 왔고, 보안(전체 분의 0.18%)을 빼고 4개 + 정상일 = 5유형이다. 우리가 정한
것은 **분류 절차**이지 범주가 아니다.

**설계 원칙 2가지** (이것만 적으면 된다)
1. **편이 아니라 (공항, 날짜)에 붙인다.** 편에 붙이면 결과로 결과를 설명하는 꼴이다 —
   BTS는 **늦은 편에만** 원인을 기록하므로 정시 편과 비교할 기준이 없다.
2. **leave-one-out.** 하루 20편짜리 공항에서는 그 편이 자기 답을 읽게 되므로 모든
   집계에서 해당 편을 뺀다. 하루 20편 미만은 아예 라벨하지 않는다(미적용 6.2%).

**원인 구성비는 공항 안에서 표준화한 뒤 argmax** — 로키산맥 옆 공항은 늘 날씨 분이
있으므로, "그 공항 기준으로 이상한 구성"이어야 그날의 특징이다.

**비지도 학습 — 무엇이고 무엇이 아닌가** (요구사항 항목이므로 반드시 넣되, 과장 금지)
같은 4개 원인 구성비에 PCA + k-means 를 돌린다. 1·2주성분이 분산의 **73.5%**,
실루엣이 최대가 되는 지점이 **k=4**(0.353), 규칙 라벨과의 ARI **0.461**.

> **이 숫자로 "유형 구분이 타당하다"고 쓰면 안 된다.** 군집과 규칙은 **같은 입력**을
> 읽으므로(표준화 범위만 다름) 일치하는 것이 당연하고, 실루엣 0.353은 강한 군집
> 구조가 아니다. 쓸 수 있는 말은 여기까지다 — *"유형 수를 4~5개로 두는 것이 데이터와
> 어긋나지는 않는다."* 유형의 **근거는 BTS의 사유 컬럼**이고, 설계가 옳았다는 증거는
> 군집이 아니라 §5.6(그날의 유형은 예측 불가)이다.

### 3.6 예측 모델 및 확률 보정 방법

**3.6.1 알고리즘 3종** — 다항 로지스틱 / XGBoost / MLP. **셋 다 10구간 확률을 출력**하게
맞춰야 비교가 성립한다. 선형용 원-핫 355열과 트리용 범주 유지, **두 벌로 전처리**한다 —
각 모델에 불리한 형태를 주면 "모델 비교"가 아니라 "형태 비교"가 된다. 이 주장은
§5.1.4에서 측정으로 확인한다.

**3.6.2 모델 A · B · C**

| | 정의 | 역할 |
|---|---|---|
| **A** | `P(y\|x)` 무조건 | ✅ **실제 배포 모델** |
| **B** | `P(y\|x, s)` 참 유형 주입 | ❌ 배포 불가. ① 천장 측정 ② C의 부품 ③ what-if 패널 |
| **C** | `Σ_s C(s\|x)·B(y\|x,s)` | ✅ 배포 가능. "분해가 정보를 만드는가" 검정용 |

**모델은 5개가 아니라 1개**라는 점을 적을 것. 유형은 **입력 칸**이지 모델을 나누는
기준이 아니다 — 5개로 나누면 ① 희귀 유형은 배울 데이터가 없고 ② 공통 규칙을 5번 다시
배우고 ③ 유형별 차이인지 모델이 달라서인지 구분할 수 없다.

**3.6.3 확률 보정**
- **왜**: 파는 것이 확률 그 자체다. 90%라 말하고 85%면 상품이 거짓말이다. 모델은
  "분포 전체가 맞게" 학습되지 "90%라 한 것이 정확히 90%"를 보장하지 않는다.
- **어떻게 재는가**: 개별 편은 검증할 수 없다(도착/미도착 둘 중 하나). **같은 확률을
  받은 편들을 모아서 센다** — 일기예보 검증과 같은 방식이고, 8개 구간 경계 전부에서 한다.
- **어느 구간으로 환산표를 만드는지도 실험으로 결정한다**(→ §5.2.1).
- 방식 4종: isotonic / temperature / prior 보정 / prior+isotonic.

### 3.7 추천 알고리즘

```
여유          = 마감 − 예정 도착            (음수면 탈락)
마감 준수 확률 = 분포에서 여유 안에 도착할 확률
보장 도착 시각 = 분포에서 요구 확률이 되는 지점
답            = 준수 확률 ≥ 요구 확률인 편 중 출발이 가장 늦은 편
```

**꼭 적을 것 — 하지 않는 두 가지**
1. **결항 확률을 다시 곱하지 않는다.** 분포는 이미 "도착할 확률"이고 미도착은 빠져
   있다. 또 곱하면 두 번 깎는 셈이다. 결항 위험은 화면에 **따로** 표시한다.
2. **보장 시각을 억지로 만들지 않는다.** 요구 확률에 도달하지 못하는 편은
   **"보장 불가"** 로 표시한다.

# 4. Experiment

### 4.1 데이터셋 구성 및 EDA

**할 말** — BTS 2021–2026년 6~8월 **10,810,813편**, 퍼블릭 도메인, 개인정보 없음.
**여름만 쓰는 이유**는 분할을 연도로 하기 때문이다 — 계절 구성이 다르면 성능 차이가
"연도 차이"인지 "계절 차이"인지 구분할 수 없으므로, 비교할 축을 하나만 남긴다.
2021년은 2022년 편의 `sched_pad` 를 계산할 직전 해 자료로만 쓴다.

**품질 점검**: 설명되지 않는 결측 **1행 / 1,081만** (숨기지 않고 센다).

### 4.2 학습·검증·보정·평가 데이터 분할

```
train  2022·2023·2024  (5,408,935)

test   2026            (1,847,936)   ← 딱 한 번만 연다
```

**무작위로 섞지 않는 이유** — 섞으면 같은 날 같은 공항의 다른 편이 양쪽에 들어가
**그날의 날씨가 샌다.** 연도 겹침이 0인 것은 누출 감사 A그룹이 확인한다.

**보정 구간 실험 설계** — 모델을 2022–23으로 재학습해 2024와 2025를 모두 미지로 만들고,
2025년 **7·8월**에서 평가한다(2025년 6월을 "직전 달"로 쓸 수 있도록).

### 4.3 비교 모델 및 알고리즘 설정

- 알고리즘 3종 비교 — 동일 분할·동일 지표
- **모델 B의 위치**: 배포 후보에서는 제외하되 **점수는 보고**한다
- **특성공학·규제 실험**: 수치형 5변수만 차수 1·2·3으로 확장하고, 채택된 차수에서 규제
  강도 C를 쓴다. 원-핫 350열은 펼치지 않는다 — 2차로 가면 약 61,000열이 되는데 그것은
  모델링이 아니라 메모리 문제이고, 지시변수 두 개의 곱은 트리가 두 번 갈라 이미 만든다.
  **같은 확장을 XGBoost에도 준다**(대조군).

### 4.4 예측 성능 및 확률 신뢰도 평가 지표

| | 지표 | 무엇을 재는가 |
|---|---|---|
| **주** | Multiclass Log Loss | 분포 전체가 맞는가 |
| **주** | **CDF 보정오차 (ECE)** | 90%라 말한 것이 실제 90%인가 |
| **최종** | **약속 이행률** | 80·90·95% 약속이 실제로 지켜졌는가 |
| 보조 | Brier Score | 꼬리에 덜 가혹한 같은 질문 |
| 보조 | AUC (15분+ 지연) | 순위 능력이 남아 있는가 |
| ~~제외~~ | ~~Accuracy~~ | 0번 클래스 57.3% → 사실상 "항상 0번 찍기" |

> **Accuracy를 왜 버렸는지 반드시 적을 것.** 가장 흔한 지표를 빼는 데는 설명이 필요하고,
> 그 설명이 이 프로젝트가 분류가 아니라 분포를 다룬다는 증거이기도 하다.

**변화 판정 기준 (숫자를 보기 전에 고정)** — 같은 설정을 시드만 바꿔 세 번 적합해 잡음의
표준편차를 재고, 그 **2배**를 "달라졌다"의 임계값으로 쓴다. 전체 학습셋에서 재면
sd **0.000125** → 임계값 **0.000251**. 사후에 기준을 정하면 아무 숫자나 근거가 된다.

### 4.5 서비스 추천 성능 평가 설계

- test 2026, 후보 2편 이상인 노선-날짜 331,544개 중 **25,000개 표본**(시드 고정)
- 마감 = 그날 마지막 예정 도착 + 60분
- **기준선 = "첫 편을 타라"**(상식)
- 평가 축 ① 마감 준수율 ② **첫 편 대비 몇 분 더 늦게 떠날 수 있나**
  ← 상식이 계산하지 못하는 것은 이 **경계**뿐이므로, 이 축에서만 이길 수 있다

> CDF 보정오차에서 XGBoost가 가장 좋다. log loss는 분포 전체의 평균 점수이고 우리가
> 파는 것은 "90%"라는 약속 한 줄이다. *"약속의 정직함을 위해 log loss 0.0044를

| 80% 약속 과보수 | +3.55%p | 필요 이상으로 일찍 떠나게 만듦 |
| 선택지 없는 노선 | 단일 편 노선-날짜 **30.8%** | "가장 늦은 편 고르기"가 성립 안 함 |
| 시뮬레이션 마감 정의 느슨 | 마지막 도착 +60분 | 답이 대체로 "마지막 편". 마감 폭 스윕은 향후 과제 |
| 합성은 1/4 부분집합 | 461,346행 | 25개 조합 × 전체는 비용 과다 |
| 유형 독립 가정 | — | 출발지·도착지 유형을 독립으로 예측해 합성 |
| 로지스틱 미수렴 | max_iter=120 | 더 돌리면 약간 개선 가능. 그대로 보고 |
| 범위 | 미국 국내선 **여름만** | 겨울·국제선 일반화 불가. 가격·실시간 정보 없음 |

**윤리 — 반 쪽 정도**
1. **약점 공개의 양면성**: OH의 84.6%를 적는 것은 특정 회사에 불리하다. 그러나 적지
   않으면 **그 손님에게는 약속이 조용히 깨진다.** 표본 수와 함께 공개하는 쪽을 택했다.
2. **잘못된 자신감의 위험**: 이 서비스는 사람을 **더 늦은 편에 태운다.** 틀리면 손해가
   실재한다. 그래서 ① 보정을 필수로 두고 ② "보장 불가"를 숨기지 않고 ③ 최종 지표를
   점수가 아니라 **약속 이행률**로 삼았다.
3. 개인정보 없음 · 퍼블릭 도메인 데이터.

# 7. Conclusion

**세 문장으로**
1. 표에 적힌 도착 시각은 57%짜리 약속이고, 우리는 **90%짜리 약속**을 만들었다
   (test 2026 실제 이행 **91.3%**).
2. 특성을 더 만들어도(§5.1.4), 모델을 바꿔도(§5.1.1), 하이퍼파라미터를 돌려도(§5.1.3)
   움직이지 않았다 — **예약 시점 정보의 천장은 AUC 0.696**, 그날을 알면 0.751.
   그 격차가 이 문제에서 **실시간 정보의 값**이다.
3. 남기는 것은 성능 숫자가 아니라 **판정의 기준**이다 — 모든 선택을 숫자를 보기 전에
   고정한 임계값으로 판정했다.
